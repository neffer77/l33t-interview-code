# Phase 19 — Company Life

Phase 19 extends Codeopolis beyond interviewing. Accepting a Phase 18 offer now unlocks a post-hire engineering simulation where career progress is downstream of real technical work rather than passive employment time.

## Product invariant

**Conversation, clicking, and time-in-role do not create career progress by themselves.**

NPC advice can help the player think, but teammate trust only increases when the related engineering stage is actually completed. Project delivery, performance reviews, and promotions are all based on judged or scored evidence from existing Codeopolis systems.

Coworker guidance covers invariants, complexity, failure modes, observability, rollback, experiments, trust boundaries, false positives, retries, deduplication, and architecture tradeoffs. The guidance does not reveal hidden-test answers.

Repeated advice clicks cannot farm trust. Each teammate can earn collaboration trust at most once per completed project stage.

## Engineering role lenses

The player can rotate the lens used to select projects and frame coworker advice:

- Algorithms
- Systems
- Reliability
- Security
- Research
- Tech Lead

A role lens changes emphasis and future challenge selection. It does not reset mastery or lock the player into a permanent path.

## Authoritative project stages

Project stages launch existing Codeopolis systems:

- **Coding:** real hidden-test mastery required.
- **Reasoning:** existing structured reasoning system, minimum 70.
- **Production incident:** existing Phase 10 incident simulator, minimum project score 65.
- **Debugging:** existing production defect scenario must be resolved.
- **System design:** existing architecture rubric, minimum 70.

Projects cannot silently attach to unrelated active incidents, debugging exercises, or design labs.

## Project scoring

Every stage stores:

- stage type
- challenge/scenario identity
- score
- weight
- timestamp

Project score is the weighted average of the evidence generated by the actual work systems.

Completed projects create a durable impact ledger and modest civilization rewards. They also emit local telemetry through the existing Phase 11 telemetry system.

## Performance reviews

Performance reviews are evidence-based rather than calendar-based. A review requires three new projects at the **current employer** since that employer's last review.

The review score combines:

- 50% project delivery quality
- 20% current Phase 16 interview/readiness evidence
- 15% teammate trust earned through completed collaboration
- 15% technical stage breadth

Bands:

- Needs Stronger Evidence
- Meets Expectations
- Exceeds Expectations
- Promotion Ready

A promotion-ready review additionally requires:

- review score >= 86
- delivery >= 82
- readiness >= 75
- teammate trust >= 10
- a remaining level on the company's ladder

## Employer isolation

Project and review evidence is scoped by employer. Moving to another company preserves old project history, reviews, promotions, and teammate relationships, but old company projects cannot satisfy a new employer's performance review.

## Local-first behavior

Phase 19 adds no backend requirement and no network analytics. Company state, project evidence, teammate trust, reviews, promotions, and role lenses persist in the normal local save.

## Learning-first rule

The strongest company progression actions remain useful learning actions:

**Own project → collaborate for context → solve/debug/design/reason for real → deliver impact → review evidence → earn promotion.**
