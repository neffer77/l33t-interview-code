# Phase 38 — Squad Projects

Phase 38 expands paired collaboration into small-team project execution.

## Goal

Make team composition a meaningful strategic layer without allowing NPCs to bypass learning or engineering assessment.

## Project loop

1. A deterministic squad project appears with three explicit risk areas.
2. The player staffs each risk with a Phase 36 relationship that has at least Working Rapport and the appropriate specialty.
3. Staffing choices establish collaboration context and support coverage.
4. Each project milestone must still be completed through an existing authoritative Codeopolis system.
5. Completed projects are archived and a new project rotates in.

## Initial projects

- Reliability Platform Launch
- Algorithm Service Expansion
- Developer Platform Migration
- Customer Trust Recovery

## Evidence authority

Milestones listen to existing events such as judged mastery, technical reasoning, incident response, system design, repository review, engineering project completion, and behavioral evaluation. Selecting a teammate never completes technical work or changes a score.

## Relationships

Staffing is constrained by actual relationship tier and role affinity. Successful shared milestones can deepen the corresponding Phase 36 relationship, making the social layer reflect demonstrated collaboration rather than passive clicking.

## Boundary

Squad projects do not modify hidden tests, interviewer rubrics, readiness, hiring, promotions, or previously earned learning evidence.
